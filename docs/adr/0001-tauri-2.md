# ADR-0001 · Tauri 2 como framework de aplicação

- **Status:** Aceita (2026-11-20)

## Contexto
O app deve ser escrito em Rust, ter visual moderno com temas claro/escuro, viver na bandeja, registrar atalhos globais e ser distribuído pela Microsoft Store.

## Decisão
Usar **Tauri 2**: núcleo e regras em Rust; interface em WebView2 (HTML/CSS/TS).

## Alternativas consideradas
- **Slint** — tudo em Rust e leve, mas tray, Mica/Acrylic e polimento visual exigem mais trabalho manual.
- **egui / iced** — produtivos, mas com visual pouco nativo no Windows.
- **WinUI 3 via windows-rs** — visual Fluent nativo, porém binding imaturo; risco técnico alto.

## Consequências
- \+ Alta produtividade de UI, ecossistema maduro de testes de frontend, tray/janelas/single-instance prontos.
- \+ Lógica 100% em Rust, já que o frontend é só apresentação (ver ADR-0002).
- − Dependência do runtime WebView2 (presente no Win11/Win10 atualizado).
- − Consumo de memória maior que UI nativa pura (meta PERF-005: ≤ 80 MB).
- − Tauri não gera MSIX nativamente (ver ADR-0007).
